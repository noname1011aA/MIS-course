# AI 開發 Agent 文件範例

本資料夾示範如何將「校園設備報修系統」的軟體規格，整理成一組 AI 開發 Agent 可以閱讀、理解並依循的文件。

## 一、為什麼需要這些文件？

如果只對 AI 說「請幫我修改報修功能」，AI 可能只根據當下的問題產生答案，卻不一定了解專案的限制、資料流程與團隊開發規則。

因此，我們將不同類型的資訊分開保存，讓 AI 能夠根據專案需求與工作規則進行開發。

這些文件分別負責：

- **軟體規格書（software-spec.md）**：說明系統需要完成的功能、限制與驗收條件。
- **Agent 工作規則（AGENTS.md）**：說明 AI Agent 在修改程式前、修改過程中及完成修改後應遵守的規則。
- **Skill（SKILL.md）**：說明特定任務可以重複使用的處理步驟與檢查流程。

## 三、核心文件介紹

### 1. README.md：專案說明文件

介紹本專案的目的、文件架構、各文件的用途，以及如何使用這組文件。

### 2. software-spec.md：軟體規格書

說明校園設備報修系統的目標、使用者、功能需求、系統限制與驗收條件。

它回答的問題是：「系統需要解決什麼問題？必須完成哪些功能才算符合需求？」

### 3. AGENTS.md：Agent 工作規則

說明 AI Agent 在本專案中扮演的角色，以及修改程式前、修改過程中和完成修改後應遵守的規則。

例如：

- 修改前先閱讀軟體規格書。
- 修改前確認受影響的檔案與預計修改方式。
- 保留既有功能與程式架構。
- 遇到需求矛盾或資訊不足時，先提出問題。
- 完成修改後，回報修改內容、測試結果與尚未確認的風險。

### 4. SKILL.md：報修功能檢查流程

說明如何按照固定流程檢查校園設備報修功能，包括檢查順序、特殊情況、驗收條件與最後的回報格式。

將重複使用的檢查步驟整理成 Skill，可以讓 AI 在處理相關任務時有一致的參考流程。

## 四、如何使用這個範例？

1. 先閱讀 `software-spec.md`，了解系統的功能需求與限制。
2. 再閱讀 `AGENTS.md`，了解 AI Agent 在專案中必須遵守的工作規則。
3. 當任務涉及報修功能檢查時，參考 `skills/repair-review/SKILL.md` 的檢查流程。
4. 根據自己小組的系統需求，調整規格書、工作規則與 Skill 的內容。
5. 修改程式後，依照規格書的驗收條件進行測試，並記錄實際結果。

## 五、如何比較有沒有這些文件的差異？

請將 `agent-files-example/` 當成一個獨立專案開啟，並建立新的 AI 開發對話。

在有文件的專案中：

- `AGENTS.md` 提供專案層級的工作規則。
- `software-spec.md` 提供系統需求與驗收依據。
- `skills/repair-review/SKILL.md` 提供報修功能的檢查流程。

接著，使用相同的功能問題，分別在沒有這些文件的專案與有這些文件的專案中詢問 AI，再比較兩者的回答與處理方式。

比較時可以觀察：

- 是否能正確理解系統需求。
- 是否會先檢查相關程式碼與檔案。
- 是否能遵守既有架構與工作規則。
- 是否有考慮例外情況與驗收條件。
- 是否能清楚回報修改內容、測試結果與尚未確認的風險。


## 六、使用注意事項

- 這些文件提供 AI 開發 Agent 專案參考，但不保證 AI 一定能正確執行所有規則。
- 不同 AI 開發工具對工作規則檔案與 Skill 的檔名、資料夾位置及載入方式可能有所不同，使用前應確認所選工具的支援方式。
- 文件中的需求與規則應隨專案實際狀況更新，避免文件內容與程式實作不一致。
- 測試結果必須以實際執行或檢查的結果為準，不得只根據程式碼推測測試已通過。
