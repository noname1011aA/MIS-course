# Repair Demo — 報修系統

## 一、專案簡介

本專案為第 H 組的 Repair Demo 報修系統功能擴充作業，依據 Tutorial 1「功能需求與開發規格書」進行開發。

本次主要改善報修者查詢案件的便利性，以及管理者記錄案件處理方式的能力。

專案以 Python Flask 作為後端，搭配 HTML、CSS 與 JavaScript 建立前端介面。

## 二、開發目標

本次功能擴充分為兩個部分：

1. **報修預計等待時間與案件排序／篩選**：讓報修者了解預計等待時間，並更方便地查看不同處理狀態的案件。
2. **後台處理敘述**：讓管理者記錄、查看及更新案件的處理方式，方便後續查閱與交接。

## 三、主要功能

### 3.1 報修預計等待時間

- 在前台案件清單中顯示預計等待時間。
- 依照確認後的案件數量及等待時間規則顯示預計結果。
- 預計時間的顯示類別包含三天內、六天內、十二天內、二十四天內及「靜候通知」。

實際計算方式與案件數量門檻，應以目前程式實作及確認後的規格為準。

### 3.2 案件排序與狀態篩選

- 依優先程度排序：緊急、急件、普通。
- 同一優先程度的案件依報修時間排序。
- 已完成案件排列在處理中及待處理案件之後。
- 可依待處理、處理中、已完成等狀態篩選案件。
- 區分沒有任何報修案件，以及目前沒有符合篩選條件的案件。

### 3.3 後台處理敘述

- 管理者將案件狀態更新為已完成並儲存後，可開啟處理敘述視窗。
- 可輸入案件的處理方式並儲存。
- 可透過文件圖示查看既有處理敘述。
- 可輸入新內容覆寫原有處理敘述。
- 尚無處理敘述時，系統會顯示相應提示。
- 不允許提交空白處理敘述。
- 找不到指定案件時，後端會回傳 HTTP 404。

## 六、相關 API

### 6.1 處理敘述更新

| 項目 | 說明 |
|---|---|
| HTTP 方法 | `PATCH` |
| 路徑 | `/api/tickets/<ticket_id>/work-note` |
| 用途 | 更新指定案件的處理敘述 |
| 資料欄位 | `work_note` |
| 成功結果 | 回傳更新結果及相關案件資料，實際格式依程式實作為準 |
| 案件不存在 | 回傳 HTTP 404 及錯誤訊息 |

前端透過 API 傳送案件編號與處理敘述，後端找到對應案件後，將新內容更新至 `ticket["work_note"]`。

其他案件查詢、建立及狀態更新 API，請以 `app.py` 中的實際路由為準。
