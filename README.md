# MIS-course
**tutorial two**# 校園設備報修系統（Repair Demo）

## 一、專案簡介

本專案為校園設備報修系統，提供報修案件登記、案件清單查看及管理後台處理等功能。

本次 Tutorial 1 作業以現有的 Repair Demo 為基礎，新增及改善報修案件的預計等待時間、案件排序與狀態篩選，以及管理後台的處理敘述功能，讓報修者更容易了解案件進度，也讓管理者能夠記錄案件的處理方式。

**專案名稱：** 校園設備報修系統（Repair Demo）

**作業名稱：** Tutorial 1－功能需求與開發規格書

**組別：** 第 H 組

## 二、主要功能

### 2.1 報修預計等待時間

系統會依照規格定義的案件數量及排序規則，顯示報修案件的預計等待時間。

預計等待時間的顯示包含以下類別：

- 三天內
- 六天內
- 十二天內
- 二十四天內
- 靜候通知

實際等待時間的計算方式及各類別對應的案件數量，應以專案正式軟體規格與實際程式實作為準。

此功能旨在讓報修者對案件可能需要等待的時間有初步了解。

### 2.2 報修案件排序與狀態篩選

系統提供案件排序及狀態篩選功能，協助使用者快速尋找需要查看的案件。

排序及篩選條件包含：

- 依報修優先程度排序：緊急、急件、普通。
- 依案件建立時間排序。
- 依案件狀態篩選：待處理、處理中、已完成。

依照目前的實作紀錄，已完成案件會排列在處理中及待處理案件之後，以便優先查看尚待處理的案件。

當篩選結果為空時，系統應區分目前沒有任何報修案件，以及目前沒有符合所選條件的案件。

### 2.3 管理後台處理敘述

管理者可以在管理後台查看及更新案件的處理敘述。

主要操作如下：

1. 管理者將案件狀態更新為「已完成」。
2. 按下「儲存狀態」，待狀態更新成功後，系統開啟處理敘述視窗。
3. 管理者輸入處理方式，並按下「確認覆蓋」。
4. 前端將案件編號及處理敘述傳送至後端。
5. 後端更新對應案件的 `work_note` 欄位。
6. 更新成功後，前端顯示成功訊息、關閉視窗並重新讀取案件清單。

管理者也可以點擊案件旁的文件圖示查看既有敘述，並以新內容覆寫原有內容。

若案件尚無處理敘述，系統會顯示相應提示；若輸入內容為空白，則應阻止送出更新請求。

## 五、資料處理與 API

### 5.1 案件資料

依照目前的實作紀錄，案件資料儲存在 Python 記憶體中的 `tickets` 清單。

本次功能涉及的主要資料欄位如下：

| 欄位 | 用途 |
|---|---|
| 案件編號 | 識別個別報修案件 |
| 案件狀態 | 表示待處理、處理中或已完成 |
| 建立時間 | 提供案件時間排序依據 |
| 優先程度 | 提供緊急程度排序依據 |
| `est_days` | 儲存預計等待天數（若實際程式採用此欄位） |
| `eta_text` | 前端使用的預計時間顯示文字（若實際程式採用此欄位） |
| `work_note` | 儲存案件處理敘述 |

上述欄位名稱應與實際程式保持一致，不應僅為配合文件而任意新增欄位。

### 5.2 處理敘述 API

處理敘述更新功能使用下列 API 路徑：

`PATCH /api/tickets/<ticket_id>/work-note`

預期處理流程：

1. 前端傳送案件編號與處理敘述。
2. 後端驗證請求資料。
3. 後端尋找指定案件。
4. 若案件不存在，回傳 HTTP 404 及錯誤訊息。
5. 若案件存在且輸入有效，更新 `work_note`。
6. 回傳更新結果，供前端顯示操作結果。

請以 `app.py` 中的實際路由及請求格式為準。

## 六、環境設定與啟動方式

本專案的實際依賴套件、啟動指令及設定方式，請先檢查專案是否包含 `requirements.txt`、環境設定檔或其他執行說明。

以下為一般 Flask 專案的啟動方式。

### 6.1 確認 Python 環境

在終端機進入專案根目錄：

```bash
cd 專案資料夾路徑
python3 --version
```

### 6.2 建立虛擬環境

如果專案尚未建立虛擬環境，可以執行：

```bash
python3 -m venv .venv
```

macOS 或 Linux 啟用環境：

```bash
source .venv/bin/activate
```

Windows PowerShell 啟用環境：

```powershell
.\.venv\Scripts\Activate.ps1
```

### 6.3 安裝依賴套件

若專案根目錄已有 `requirements.txt`：

```bash
python -m pip install -r requirements.txt
```

若沒有依賴清單，應先檢查專案實際使用的套件，再依照原有環境設定安裝，不要直接假設所有依賴。

### 6.4 啟動 Flask

若專案以 `app.py` 中的 Flask 應用程式作為啟動入口，且該檔案支援直接執行：

```bash
python app.py
```

若程式未設定直接執行入口，可依實際應用程式名稱使用 Flask CLI：

```bash
flask --app app run
```

請以終端機顯示的實際網址為準。若使用 Flask 預設設定，通常可在瀏覽器開啟：

`http://127.0.0.1:5000`

若管理後台路徑為 `/admin`，則可開啟：

`http://127.0.0.1:5000/admin`

以上網址為一般 Flask 執行方式的範例，實際路由應以專案程式碼為準。

## 七、測試與驗收

修改功能後，應依照 `software-spec.md` 的驗收條件進行檢查。

### 7.1 預計等待時間

- 確認報修案件會顯示預計等待時間。
- 檢查不同案件數量下的等待時間。
- 檢查等待時間的邊界條件。
- 確認等待時間符合既定的排序與計算規則。

### 7.2 排序與篩選

- 確認緊急、急件及普通案件的排序。
- 確認同優先程度案件的時間排序。
- 確認待處理、處理中及已完成篩選結果正確。
- 確認沒有符合篩選條件的案件時，顯示正確提示。

### 7.3 後台處理敘述

- 確認案件狀態更新成功後可開啟處理敘述視窗。
- 確認可以新增及查看處理敘述。
- 確認新內容能正確覆寫舊內容。
- 確認空白內容不會送出更新。
- 確認案件不存在時，後端會回傳 HTTP 404。
- 確認關閉視窗不會意外儲存未確認的內容。

測試完成後，應記錄實際測試步驟、結果及尚未確認的問題，不得在未執行測試時宣稱全部通過。
